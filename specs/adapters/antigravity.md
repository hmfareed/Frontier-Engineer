# Antigravity adapter — implemented

**Status:** Implemented in Phase 2. Format verified against official documentation and the locally installed `agy` CLI 1.5.0 on 2026-11-10. See [the verification record](../../docs/27-OFFICIAL-FORMAT-VERIFICATION.md).

## Verified target format

Antigravity discovers custom agents at `<plugin-root>/agents/<name>.md` (also `agents/<name>/agent.md`), scans one level deep, and reads YAML frontmatter followed by a Markdown system prompt.

Frontmatter fields used by this adapter: `name`, `description`, `mainAgent`, `subagent`, `model`, `commandExecutionPolicy`. All six appear in the official [Custom subagents](https://antigravity.google/docs/subagents) and [Build plugins](https://antigravity.google/docs/build-plugins) documentation.

| Canonical field                    | Antigravity mapping                                              |
| ---------------------------------- | ---------------------------------------------------------------- |
| `id`                               | `name`                                                           |
| `summary`                          | `description` (the planner's delegation trigger)                 |
| `kind: coordinator`                | `mainAgent: true`, `subagent: false`                             |
| `kind: specialist`                 | `mainAgent: false`, `subagent: true`                             |
| `platformConfig`                   | Frontmatter generated by the adapter; canonical stays empty      |
| capability / approval requirements | Prompt-level restrictions plus `commandExecutionPolicy: sandbox` |

## Deliberate omissions

- **`tools` allowlist:** not emitted. The official documentation conflicts on the default (`[]` in the custom subagents reference versus "all tools" in the plugin guide) and warns that an unmapped or misspelled tool name can hang a subagent. No authoritative enumeration of tool identifiers was found, so behavior-level least privilege is used instead. This is recorded as a known limitation.
- **`skills`:** not emitted. The ten engineering skills belong to Phase 3 and do not exist yet.
- **`mcpServers`:** not emitted. MCP integrations belong to Phase 5 and are optional.
- **`inheritMcp` / `inheritCustomizations`:** not emitted. They appear in the plugin guide but not in the custom subagents reference; platform defaults are used rather than asserting unverified keys.

## Delegation and communication

The coordinator delegates with the verified `invoke_subagent` tool. Subagents start with a clean context, run concurrently, and return a result message to the parent. Inter-agent messages use conversation IDs; nesting is limited to 10 levels. The [handoff contract](../handoff-contract.md) fields are carried in the delegation prompt and parsed from the result message by the coordinator — this is a structured convention, **not** a claim that Antigravity natively validates the contract.

`agy plugin validate --strict .` validates manifest and component discovery. Runtime invocation of these agents has **not** been tested; see [known limitations](../../docs/04-AGENT-SPECIFICATIONS.md).

## Regeneration

Generated files are written to `agents/`. Edit [the canonical specifications](../agents/) and rerun `npm run generate:agents`; never edit generated files directly.
